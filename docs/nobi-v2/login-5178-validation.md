# 5178 线上账号登录验证

2026-10-11：用户要求在 `http://127.0.0.1:5178` 验证，并明确选择使用现有线上账号。

## 原因与修复

原地址没有运行中的开发服务；默认开发配置没有 Supabase URL/anon key，登录无法认证。登录与注册页面还在等待配置完成之前读取 `window.APP_CONFIG`，异步加载期间点击按钮会直接失败。

- 新增 `npm run dev:online`，从 `CNAME` 所指游戏官网的公开 `/get-config` 接口读取 URL/anon key，经现有公开配置校验后启动 5178。
- 此模式仅适用于开发，使用独立 `.nobi-stage/online`，不修改本地公开配置文件、默认离线构建或隔离测试后端。
- 服务仅监听 `127.0.0.1`。线上公开配置获取失败时启动失败；不使用高权限密钥，不记录 anon key、密码或会话。
- 登录和注册统一等待 `NobiServices.requireClient()` 完成配置初始化；登录要求返回有效的用户与会话。

## 使用

```powershell
npm run dev:online
```

打开 `http://127.0.0.1:5178/login.html`，直接在页面输入现有线上账号。普通 `npm run dev` 继续使用已有本地配置；未提供配置时只适合本地单机预览。

已有服务运行时，可以在另一个终端执行：

```powershell
npm run test:login:5178
```

测试读取真实认证服务的公开 settings 接口；账号密码错误、有效会话与注册失败使用拦截在本机的测试接口。测试不尝试登录、注册或修改任何线上账号，不录制含认证信息的 trace/video，也不停止已运行的 5178 服务。
